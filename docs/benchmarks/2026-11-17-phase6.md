# Phase 6 local measurement — 2026-11-17

**Scope:** Apple M4, 16 GB; `ffmpeg-full` 9.0.2. These are short local probes of
F1 broadcast source excerpts, not a representative three-hour gaming stream.
Each encoder setting ran once on a six-second interval through ClipOS's actual
1080×1920 composition/caption graph. SSIM compares decoded outputs with a lossless
FFV1 render of that same composition. It screens compression loss; it does not
measure appeal, HUD legibility or upload readiness. Raw measurements are in the
adjacent [JSON report](2026-11-17-phase6.json). No paid model call was made.

Synthetic tagged PQ and HLG inputs now convert to BT.709 SDR before composition;
the tested PQ final and HLG preview outputs are H.264/AAC/yuv420p with BT.709
tags. A variable-frame-rate input produced an explicit 60 fps CFR final. A frame
from one F1 final showed the broadcast HUD and caption inside the image; the
default full-frame-preserving layout leaves large empty vertical areas. Output
metadata checks passed for A/V duration alignment; perceptual sync and real HDR
color appearance have not been assessed.

RQ 2.6.1 plus redis-py 7.1.0 completed private TCP SpawnWorker jobs with its
scheduler and the backend test suite. Redis-py 8.1.0 failed the same spawn test
because its connection argument representation was not reconstructable; Unix
socket spawning failed with an unexpected `path` argument. The worker therefore
uses SpawnWorker for macOS TCP Redis and retains the fork worker for explicit Unix
socket configurations. The scheduler can still emit a macOS fork warning; this
package does not claim to eliminate every process fork.

**Open acceptance measurements:** cold-cache three-hour end-to-end wall time,
first usable preview, real gaming clip acceptance/corrections, peak whole-system
memory, actual API cost and three-run variability. The product's roughly ten
upload-ready clips in twenty minutes remains unverified. A short-source real-time
factor must not be extrapolated into that claim.
